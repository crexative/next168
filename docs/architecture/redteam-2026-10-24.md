**Verdict: revise before implementation.** Three blockers undermine approval enforcement and data preservation.

Reviewed [deliverable-1.md](../../docs/architecture/deliverable-1.md) (“A” below) at `f4597a97dab396b6a6c19d64010eeabf75ab7b9b`, its research inputs, current code, and the linked GOAL. Primary sources accessed **2026-10-24 UTC**. These are design findings, not reproduced implementation vulnerabilities. Remote-ref refresh and calendar header probes failed because shell DNS was unavailable; subscription CORS behavior and model download totals remain independently unverified.

1. **BLOCKER — UI token does not establish human approval.**  
   **§2 D6 / §4; A:23,74–75.** A client with HTTP or browser tools can fetch the companion page, obtain `window.__NEXT168__.uiToken`, and call either apply or unrestricted document PUT. Browser automation can also press Approve. Rejecting the MCP token proves only token separation.  
   **Smallest fix:** define the client threat boundary and place approval authority outside agent-accessible capabilities, binding approval to the exact diff and revision. A page-injected bearer token cannot prove human presence.

2. **BLOCKER — localStorage revisions cannot provide atomic compare-and-save.**  
   **§2 D4; A:21.** Two tabs both read revision 12, both validate `expectedRevision=12`, then overwrite each other with revision 13. A later `storage` event cannot restore the lost edit. The [HTML Standard](https://html.spec.whatwg.org/multipage/webstorage.html) explicitly advises assuming no locking.  
   **Smallest fix:** serialize every browser commit and migration using an exclusive Web Lock, re-read inside it, and fail closed where unavailable—or use transactional IndexedDB. Add a synchronized two-tab race test.

3. **BLOCKER — an old application can overwrite migrated data.**  
   **§2 D2 / §3 migration; A:19,66.** An already-open v1 tab continues writing `next168-data` after v2 migration. Its [save path](../../src/stores/weekStore.ts:233) contains only categories and timeBlocks, deleting tasks, actuals, events, and proposals. New-code stale-tab guards cannot constrain old code.  
   **Smallest fix:** commit v2 under a new key; preserve the legacy key as migration input. Test an actual v1 writer remaining open during migration.

4. **MAJOR — the migration is explicitly lossy.**  
   **§3; A:52,66.** Legacy [TimeBlock.description](../../src/types/index.ts:13) has no specified mapping to `notes`; arbitrary hex colors become nearest palette colors. The listed fixtures could pass while users lose descriptions and exact colors.  
   **Smallest fix:** specify `description → notes` and preserve legacy color values, even if presentation uses a palette. Assert field-level preservation.

5. **MAJOR — proposals can stale themselves; replay semantics are undefined.**  
   **§3 / §4; A:38,49,59,75.** A proposal based on revision 7 is persisted inside the document, advancing it to 8; approving its unchanged base revision then fails. Restore/import can also reuse revision numbers across unrelated documents.  
   **Smallest fix:** distinguish planner-content revision from proposal metadata, add workspace identity, make proposal contents immutable, and atomically transition pending→applied with an idempotent result. Test duplicate delivery, concurrent approval, and response loss after commit.

6. **MAJOR — “atomic write + backup” is not a recovery protocol.**  
   **§2 D2–D5; A:19–22.** Backup creation can exceed quota; disk-full can interrupt file replacement; concurrent HTTP handlers can both accept one revision. Awaiting save does not specify whether failed writes leave optimistic UI mutations visible.  
   **Smallest fix:** define candidate→validate→serialized durable commit→publish ordering, preserve the original on every failure, and specify temp-file flush/rename and backup recovery. Inject quota, permission, crash, and concurrent-request failures.

7. **MAJOR — changing modes or installing on iOS can appear to erase everything.**  
   **§2 D5 / §5 S4; A:22,91.** Hosted/browser storage and companion storage are separate, but the design omits the explicit transfer flow recommended in [connectivity research](../../docs/research/llm-connectivity.md:31). Apple also documents that [Home Screen installation does not copy localStorage](https://webkit.org/blog/14787/webkit-features-in-safari-17-2/).  
   **Smallest fix:** show workspace/mode identity and provide deliberate export/import with read-back verification, including installation guidance. Preserve originals.

8. **MAJOR — editing the template rewrites historical measures.**  
   **§3; A:55,68.** Monday’s completed block records only `blockId`. Changing its duration/category on Tuesday changes Monday’s inferred actuals; deleting it leaves an orphan. Optional minutes and undefined partial-status semantics compound this.  
   **Smallest fix:** snapshot category and planned duration on dated occurrences, define actual-minute semantics and uniqueness, and preserve history across template edits/deletion.

9. **MAJOR — the week ring is insufficient for dated time.**  
   **§3; A:34–40,52,68–70.** During Europe/Berlin’s 2026-10-25 fallback, 02:30 occurs twice; a civil week contains 169 elapsed hours. Minute-only sleep, fitting, and event comparisons cannot distinguish them. Equal start/end also becomes a surprising 24-hour block.  
   **Smallest fix:** separate nominal weekly-template minutes from zoned dated intervals; define DST gap/fold policy, date anchoring, half-open boundaries, week-start mapping, and equal-time behavior. Test Saturday→Sunday wrap and both DST transitions.

10. **MAJOR — calendar persistence cannot reconstruct future weeks correctly.**  
    **§2 D7 / §3; A:24,57–58.** File sources retain neither source content nor recurrence definitions, while expansion covers only the visible week. After reload/navigation, later occurrences cannot be regenerated. UID alone lacks recurrence-instance identity. Timezone and all-day interpretation remain unspecified; [ical.js ships no registered timezone database](https://kewisch.github.io/ical.js/api/), and [RFC 5545](https://www.rfc-editor.org/rfc/rfc5545) specifies exclusive event ends.  
    **Smallest fix:** retain source data and exceptions, identify occurrences by source/UID/recurrence ID, define DATE versus instant/floating-time types, and specify timezone resolution. Test EXDATE, moved instances, cross-week spans, and offline navigation.

11. **MAJOR — ICS proxy and expansion limits remain bypassable.**  
    **§2 D7 / §4; A:24,76.** A hostname can resolve publicly during validation and privately during connection. A tiny SECONDLY recurrence beginning decades ago can exhaust CPU despite the 5 MB/10 s fetch limits.  
    **Smallest fix:** validate and pin connection addresses, handle IPv6/mapped addresses and every redirect, strip credentials, and bound decompressed bytes, occurrences, and expansion work. [OWASP describes the DNS-pinning risk](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html). Exact inbound Host checks remain necessary.

12. **MAJOR — PWA caching conflicts with companion authentication and upgrades.**  
    **§2 D8 / §4; A:25,74.** Precaching/navigation fallback can retain token-bearing HTML; rotating the companion token then leaves installed clients using stale credentials. Prompt-to-update does not define handling for pending edits or incompatible schemas across tabs.  
    **Smallest fix:** cache a token-free shell, fetch bootstrap credentials through a noncached authenticated path, fail closed, and define a commit/reload compatibility barrier. Test companion restart and an upgrade with dirty tabs.

13. **MAJOR — acceptance checks can pass while calendar/PWA outcomes fail.**  
    **§6, criteria 2,6–8; A:102,106–108.** Self-parsing ICS and inspecting link parameters do not prove correct import, attendee handling, or subscription refresh. File fallback does not verify URL support. Chrome can [install pages that fail PWA criteria](https://web.dev/articles/install-criteria), so a menu item is insufficient evidence.  
    **Smallest fix:** verify external-calendar outcomes and document a tested provider/CORS matrix. Exercise manifest start_url/scope, SW control, launch, and offline data at both `/` and `/next168/`. Relative base is supported by the [plugin resolver](https://raw.githubusercontent.com/vite-pwa/vite-plugin-pwa/main/src/utils.ts); portability still requires testing.

14. **MAJOR — “contracts first” freezes too little for parallel work.**  
    **§5; A:82–93,113.** S1 needs task placements produced by S2, but no placement contract exists. Repository result/error types, scheduler clock inputs, category CRUD ownership, and shared-shell wiring are unspecified. S0-core’s `src/core/**` ownership overlaps S3.  
    **Smallest fix:** freeze those interfaces and assign shared-file/integration ownership before parallel implementation.

15. **MINOR — AI breadth exceeds demonstrated need.**  
    **§2 D9 / §6 criterion 8; A:26,108.** Three providers and a large default add unmeasured integration work while acceptance exercises only 1B. WebLLM’s worker names are [correct](https://webllm.mlc.ai/docs/user/advanced_usage.html); its [schema parameter is a string](https://raw.githubusercontent.com/mlc-ai/web-llm/v0.2.86/src/openai_api_protocols/chat_completion.ts), and Gemma requires approximately [3,387 MB VRAM plus shader-f16](https://raw.githubusercontent.com/mlc-ai/web-llm/v0.2.86/src/config.ts).  
    **Smallest fix:** ship one verified model/provider first; freeze serialized-schema calls and test OOM, cancellation, device loss, and offline reload before expanding.
