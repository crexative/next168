The performance test verifies all original input hashes and every original placement with the frozen per-task reference using its old ten-minute minimum. It then toggles exactly one condition, from `minutes < 10` to `minutes < min(10, remaining)`, checks the corrected reference against fixed SHA-256 hashes, and compares every production placement with that reference. No placement differences are ignored. The 200 seeded planner comparisons use the independent corrected reference too.

Previous and pinned fixture inputs now come from the original recorded placements. Previously the supposedly frozen reference imported the production minute scheduler, so fixing it also changed those inputs before their hashes could be checked.

Why other tasks move: tasks reserve time in deadline, priority, creation and ID order. A newly accepted final chunk occupies time that used to be free; its end still reserves through the next five-minute grid point. Later tasks therefore see different windows, and can split, move, miss a deadline, or lose a previously usable fragment. Keeping the old placements would double-book that recovered time or strand the remainder again. The greedy algorithm does not maximize total placed minutes: completing earlier tasks can reduce the total when their snapped reservations leave gaps too small to start later tasks. Neither ordering nor grid reservation rules changed.
